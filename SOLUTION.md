# SMILES-2026 Hallucination Detection Solution

## 1. Overview

This repository contains my solution for the **SMILES-2026 Hallucination Detection** technical project.

The task is binary hallucination detection for responses generated by `Qwen/Qwen2.5-0.5B`.

For each prompt-response pair, the model extracts internal hidden states from the language model and trains a lightweight probe classifier to predict whether the response is:

- `0` — truthful;
- `1` — hallucinated.

The final solution modifies only the three allowed files:

- `aggregation.py`
- `probe.py`
- `splitting.py`

The rest of the provided infrastructure was kept unchanged.

## 2. Reproducibility

### 2.1. Environment setup

Clone the repository and install the required dependencies:

```bash
git clone https://github.com/mshded/SMILES-HALLUCINATION-DETECTION
cd SMILES-HALLUCINATION-DETECTION

python -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

For Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2.2. Running the full solution

To reproduce the submitted results and generate predictions:

```bash
python solution.py
```

This script:

1. loads the provided labelled dataset from `data/dataset.csv`;
2. extracts hidden states from `Qwen/Qwen2.5-0.5B`;
3. aggregates hidden-state representations into feature vectors;
4. evaluates the probe using repeated stratified train/validation/test splits;
5. writes internal evaluation metrics to `results.json`;
6. generates final predictions for `data/test.csv`;
7. writes the submitted predictions to `predictions.csv`.

Output files:

```text
results.json
predictions.csv
```

## 3. Final Approach

The final solution is based on three main choices:

1. reduced multi-layer hidden-state aggregation;
2. a small regularized MLP probe;
3. repeated stratified train/validation/test splits.

---

## 4. Feature Aggregation

The original baseline used only the last real token representation from the final transformer layer, producing a feature vector of size `896`.

In the final solution, I use a compact multi-layer aggregation strategy.

For each prompt-response pair, I concatenate four representations:

1. final transformer layer, last real token;
2. final transformer layer, mean pooling over the last 32 real tokens;
3. layer `-4`, last real token;
4. layer `-8`, last real token.

Since `Qwen/Qwen2.5-0.5B` has hidden dimension `896`, the final feature dimensionality is:

```text
4 × 896 = 3584
```

This aggregation scheme gave a better trade-off than both the original single-vector baseline and larger multi-layer representations.

### Motivation

The final-layer last-token representation alone may miss useful information distributed across the response sequence and intermediate layers.

Mean pooling over the last 32 tokens adds local response level context, while representations from layers `-4` and `-8` provide additional intermediate level signals.

At the same time, I avoided using too many layers because larger feature vectors caused stronger overfitting on the small labelled dataset.

---

## 5. Probe Classifier

The final classifier is implemented in `probe.py` as a small MLP.

The architecture is:

```text
StandardScaler
Linear(input_dim → 128)
LayerNorm
ReLU
Dropout(0.35)

Linear(128 → 32)
ReLU
Dropout(0.15)

Linear(32 → 1)
```

The model is trained with:

```text
loss: BCEWithLogitsLoss
optimizer: AdamW
learning rate: 3e-4
weight decay: 5e-3
epochs: 80
gradient clipping: 1.0
```

Because the dataset is imbalanced, the loss uses `pos_weight` computed from the class distribution in the training split.

The decision threshold is tuned by validation accuracy.

This was selected because the project ranking metric is based on hard-label accuracy, and accuracy-based threshold tuning performed better than F1-based threshold tuning in the experiments.

For the final `predictions.csv`, the provided `solution.py` trains the final probe on all labelled data by calling `fit()` directly.

Therefore, the implementation also sets a fallback threshold after training in `fit()`. During internal evaluation, this threshold is overridden by `fit_hyperparameters()` using the validation split.

---

## 6. Splitting Strategy

The original template used a single stratified train/validation/test split.

In the final solution, I use five repeated stratified train/validation/test splits.

Each split preserves the class ratio and contains:

```text
train: 481 samples
validation: 104 samples
test: 104 samples
```

This makes the internal evaluation more stable than relying on a single random split.

The splits are generated with different random seeds:

```text
seed = random_state + split_id
```

This ensures that all five folds are different while still being reproducible.

## 7. Final Internal Evaluation Results

The final run produced the following average metrics over five repeated stratified splits:

| Metric | Majority baseline | Final model |
|---|---:|---:|
| Accuracy | 70.19% | 72.69% |
| F1 | 82.49% | 82.92% |
| AUROC | — | 65.29% |

The final model improves both main hard-label metrics over the majority-class baseline:

```text
Accuracy: 70.19% → 72.69%
F1:       82.49% → 82.92%
```

Since the primary ranking metric is accuracy, the final model was selected based on its improvement in average test accuracy.

## 8. Experiments

### 8.1. Larger multi-layer aggregation, 5376 features

I first tried a larger aggregation scheme using:

- final layer, last token;
- final layer, tail mean pooling;
- layer `-2`, last token;
- layer `-4`, last token;
- layer `-8`, last token;
- layer `-12`, last token.

This produced a `5376`-dimensional feature vector.

The larger feature vector slightly improved accuracy in some runs, but it did not reliably improve F1 over the majority baseline.

It also caused strong overfitting: train AUROC was close to 100%, while test AUROC remained much lower.

Because of this, I reduced the aggregation scheme to four representations and removed layers that appeared to add noise.

---

### 8.2. Threshold tuning by F1

I compared threshold tuning by validation F1 and validation accuracy.

F1-based tuning did not improve the final hard-label behavior.

Accuracy-based tuning produced better average test accuracy and similar or better F1, so the final solution uses threshold tuning by validation accuracy.

---

### 8.3. PCA + Logistic Regression

I tested a simpler linear probe:

```text
StandardScaler
PCA
LogisticRegression
```

The motivation was to reduce overfitting caused by the MLP.

This approach reduced the train/test gap, but it also significantly reduced test performance.

The average test F1 dropped far below the majority baseline, so this direction was discarded.

A likely reason is that PCA preserves directions with high variance, not necessarily directions that are most predictive for hallucination detection.

---

### 8.4. Reduced aggregation, 2688 features

I also tested a smaller aggregation scheme using only:

- final layer, last token;
- final layer, tail mean pooling;
- layer `-4`, last token.

This produced a `2688`-dimensional feature vector.

This version reduced the feature dimension, but performance decreased compared with the final `3584`-dimensional version.

Removing the layer `-8` representation likely removed useful signal.

Therefore, the `3584`-dimensional aggregation was selected.

---

### 8.5. Smaller MLP, 96 → 24

To reduce overfitting, I tested a smaller MLP:

```text
Linear(input_dim → 96)
LayerNorm
ReLU
Dropout(0.40)

Linear(96 → 24)
ReLU
Dropout(0.15)

Linear(24 → 1)
```

This reduced train performance, but it did not improve test performance.

Both test F1 and test AUROC were lower than in the final model.

Therefore, the `128 → 32` MLP was kept.

---

### 8.6. Additional geometric features

I also tested additional compact features based on:

- representation norms;
- cosine similarities between selected layers;
- L2 representation drift between layers;
- tail hidden-state variability;
- relative sequence length.

These features did not improve the result over the hidden-state-only model.

The final solution therefore uses:

```text
USE_GEOMETRIC = False
```

---

## 9. Discussion and Limitations

The final model improves over the majority baseline in both accuracy and F1, but it still has important limitations.

The main limitation is overfitting.

The average train AUROC is much higher than the average test AUROC:

```text
avg_train_auroc = 0.9989655457
avg_test_auroc  = 0.6529385771
```

This means that the MLP can fit the small labelled dataset very well, but the probability ranking quality on held-out splits is limited.

The model has such behavior because:

1. the labelled dataset is small;
2. the class distribution is imbalanced;
3. the majority baseline is already strong, especially in F1;
4. hidden-state features are high-dimensional relative to the number of labelled examples.
